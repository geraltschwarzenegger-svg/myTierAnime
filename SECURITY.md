# Безопасность myTierAnime

Обновлено 11 октября 2026. Здесь описаны реализованные меры и их границы.
Это не независимый аудит и не гарантия отсутствия всех уязвимостей.

## Два варианта публикации

**GitHub Pages** раздаёт HTML и публичный `data.json`. Он не предоставляет
серверный вход или базу аккаунтов. Защита скриптов задана через CSP в HTML:
встроенный JavaScript разрешён по SHA-256, внешние скрипты — с собственного
источника. `unsafe-inline` и `unsafe-eval` для скриптов не разрешены.
Шрифты и html2canvas находятся локально; html2canvas подключён с SHA-384 SRI.
CSS допускает встроенные стили для существующего интерфейса.

**Cloudflare Workers + D1** добавляет серверный вход и HTTP-защиту.
Эта версия протестирована локально, но отдельный production-сервер пока
не опубликован: в конфигурации остаются примеры ID базы и адреса владельца.

| Мера | Реализация |
|---|---|
| Сессии | подписанная `HttpOnly; Secure; SameSite=Lax` cookie, срок 14 дней |
| Выход | удаление HMAC-отпечатка сессии из D1; прежняя cookie больше не работает |
| Почтовые коды | HMAC в базе, срок 15 минут, не более пяти попыток; атомарное погашение |
| Конкурентные запросы | атомарный счётчик частоты и резервирование попыток в SQL |
| CSRF | обязательный `x-atl-request: 1`, проверка Origin и Sec-Fetch-Site; CORS не открыт |
| Размер запроса | чтение потока с лимитом UTF-8 байтов: список 512 KiB, отзыв 32 KiB, прочее 8 KiB |
| Валидация списка | до восьми тиров и 2000 тайтлов; уникальные ID, длины строк, настоящие даты |
| Заголовки | CSP, `frame-ancestors 'none'`, DENY, nosniff, no-referrer, COOP и ограничения Permissions-Policy |
| HTTPS | HSTS на HTTPS-ответах; в локальной HTTP-разработке не включается |
| Ошибки | внутренние исключения, SQL и трассировки не возвращаются клиенту |

Обновлённую `site/schema.sql` нужно применить перед развёртыванием кода:
она добавляет таблицу сессий без удаления коллекций. Старые cookie потребуют
повторного входа. `SESSION_SECRET` должен содержать не менее 32 байтов
случайного материала. Короткий или отсутствующий ключ блокирует API входа.

Отладочный код входа возвращается только при `DEV_ECHO_CODE=1`, отсутствии
почтового ключа и адресе localhost/127.0.0.1/[::1]. На публичном домене он
не возвращается даже с этим флагом. В production нужна работающая почта.

## Данные и изображения

Текст из JSON выводится как текст или экранируется. Обложки и пользовательские
фоны допускают HTTPS без логина/пароля либо растровый data-URL PNG/JPEG/WebP/GIF.
URL с javascript, file, HTTP, управляющими символами и SVG data-URL отклоняются.
Импортируемый JSON ограничен 8 MiB до чтения. Существующая небезопасная ссылка
в локальном JSON не загружается, сам импортированный снимок не переписывается.

Обложки с внешних HTTPS-хостингов могут сообщать этим хостингам IP посетителя.
Referrer-Policy скрывает URL страницы. Фон, альбом и портреты встроены в HTML.
Автономный HTML сохраняет собственный загрузчик; веб-CSP относится к собранным
`index.html`, а серверные заголовки — только к версии Worker.

Пароль коллекции шифрует локальные сохранения AES-GCM-256; ключ выводится
PBKDF2-SHA256 с 250 000 итерациями. **Опубликованный список остаётся публичным**:
локальный пароль не закрывает `data.json` на GitHub или опубликованную страницу
Worker. Для резервных копий храни пароль отдельно от файла.

GitHub-токен публикации хранится в `sessionStorage`, а не `localStorage`.
При обновлении старое постоянное сохранение переносится в текущую сессию и
удаляется. Используй короткоживущий fine-grained токен с доступом только
к нужному репозиторию. Код, выполняющийся на том же источнике, способен читать
sessionStorage: это ограничение срока хранения, а не шифрованное хранилище.

## Проверка и сопровождение

```bash
python3 tools/mksite.py src/app.html index.html
python3 tools/mksite.py src/app.html site/public/index.html
node --test tools/test/persistence.test.mjs site/test/worker.test.mjs site/test/security.test.mjs
```

49 тестов проверяют в том числе атаки через URL, CSRF, повторное использование
cookie, параллельное погашение кода, границы размера потока и SHA/SRI сборки.
В Chromium дополнительно проверены блокировка постороннего скрипта, работа
без внешних шрифтов/CDN, сохранения и экспорт. Серверный сценарий запускается
с настоящим локальным Worker и D1.

Обновляй локальные зависимости с проверкой источника, лицензии и новой SRI;
после правок встроенного JavaScript пересобирай CSP. Не коммить `.dev.vars`,
API-ключи, cookie, GitHub-токены или локальную базу: эти файлы исключены из Git.
Если обнаружена уязвимость, сообщи владельцу репозитория приватно; не прикладывай
действующие ключи и персональные данные в публичный issue.
