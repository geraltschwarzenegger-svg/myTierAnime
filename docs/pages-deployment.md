# Публикация GitHub Pages

Сайт использует штатную публикацию Pages из `main` → `/`. Адрес и версия V5.0.0 сохранены. `_config.yml` ограничивает состав публикации, а workflow `.github/workflows/pages.yml` отдельно проверяет сайт и данные.

## Почему появлялся красный статус

09.11.2026 публикация корня репозитория завершилась таймаутом на `syncing_files`; повторная попытка осталась в очереди. Сборка приложения прошла, ошибка возникла при переносе файлов на Pages. Артефакт занимал 91 437 980 байт и включал исходники, тесты, серверную копию, автономный HTML и архивы.

Размер сам по себе не доказывает причину сбоя сервиса. Новая конфигурация устраняет ненужные файлы и не требует изменения режима Pages через административный API, недоступный текущему GitHub-доступу (HTTP 403).

## Что публикуется

Сохраняются `index.html`, оба актуальных JSON, `assets/`, изображения документации и небольшие файлы документации. `_config.yml` исключает исходники, Worker, инструменты, тесты, ZIP, старый снимок и автономные HTML. Они остаются в репозитории и доступны по прежним GitHub/raw-ссылкам.

`tools/build-pages.py` также готовит изолированную проверочную директорию `.pages-build/`: приложение, оба JSON, ресурсы, изображения документации, `SECURITY.md` и технический `build-info.json`. Она занимает около 31,6 МБ и используется тестом состава сборки; сама директория не коммитится и не публикуется отдельным конкурирующим процессом.

## Как проверяется успех

1. Actions → `pages build and deployment`: `build` и `deploy` должны завершиться успешно.
2. Actions → `Verify ASTRAVA website`: должны пройти тесты данных, CSP, безопасности и состава публикации.
3. На публичном сайте должны открываться новые фотографии, а `data.json` совпадать с опубликованной коллекцией.

Старые неудачные попытки остаются в истории развёртываний. Их не удаляют и не помечают успешными вручную: текущий зелёный статус создаёт настоящая успешная публикация.

## Обслуживание

- Проверочный workflow запускается для `main` или вручную; он не развёртывает сайт и не конкурирует со штатным Pages.
- Actions закреплены по проверенным SHA официальных релизов; используется Node.js 24.
- Тест проверяет исключение исходников и архивов из Pages и наличие всех ресурсов сайта.
- Если появляются новые служебные папки или большие архивы, их следует добавить в `_config.yml`.
- ZIP и данные коллекции при этом исправлении не менялись.
