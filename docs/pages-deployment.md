# Публикация GitHub Pages

Сайт публикуется workflow `.github/workflows/pages.yml` из ветки `main` в существующее окружение `github-pages`. Адрес и версия V5.0.0 сохраняются.

## Почему заменили старую публикацию

09.11.2026 автоматическая публикация корня репозитория завершилась таймаутом на `syncing_files`; повторная попытка осталась в очереди. Сборка приложения прошла, ошибка возникла при переносе файлов на Pages.

Прежний артефакт `github-pages` занимал 91 437 980 байт. Он содержал исходники, тесты, серверную копию, автономные HTML и архивы. Эти файлы не нужны для работы опубликованного интерфейса. Размер сам по себе не доказывает причину сбоя сервиса; новая схема устраняет ненужный объём и делает публикацию воспроизводимой.

## Что загружается теперь

`python3 tools/build-pages.py` готовит `.pages-build/`:

- `index.html` — тот же проверенный интерфейс;
- `data.json` и синхронный резервный JSON;
- `assets/` — локальные постеры, новые фотографии альбома, иллюстрации, шрифты и библиотека экспорта;
- `docs/images/` — изображения документации и Open Graph;
- `SECURITY.md`, `.nojekyll` и `build-info.json`.

Исходники, Worker, инструменты, тесты, ZIP и отдельный автономный HTML в Pages-артефакт не попадают. Они остаются в GitHub-репозитории. Сами ZIP и данные коллекции при этом не изменяются.

## Как проверить

1. Открыть Actions → «Publish ASTRAVA to GitHub Pages» и дождаться успеха `build` и `deploy`.
2. Проверить `/myTierAnime/build-info.json`: `sourceCommit` должен совпадать с опубликованным коммитом.
3. Проверить новые фотографии в альбоме и неизменность опубликованного JSON.

Старые неудачные попытки остаются в истории развёртываний. Их не удаляют и не помечают успешными вручную: текущий зелёный статус создаёт настоящая успешная публикация.

## Обслуживание

- Workflow запускается при изменении `main` или вручную; тестовая ветка лаборатории не публикуется.
- Все Actions закреплены по проверенным SHA официальных релизов; обновление версий выполняется осознанно.
- До загрузки артефакта выполняются тесты данных, CSP, безопасности и состава сборки.
- Одна новая публикация заменяет предыдущую; устаревшие параллельные запуски отменяются.
- Временный файл сборки защищён маркером, чтобы сборщик не удалял произвольную существующую папку.
