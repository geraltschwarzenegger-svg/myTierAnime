# Тир-лист как настоящий сайт

Приложение с сервером и базой: вход по коду на почту, у каждого свой список по
адресу вида `/geralt`, обратная связь с письмами и еженедельная сводка.
Всё это — на Cloudflare Workers + D1, без своего сервера и без платы на
бесплатном тарифе.

```
site/
  wrangler.toml         настройки развёртывания
  schema.sql            таблицы базы
  src/index.js          сервер целиком
  public/index.html     фронтенд (собирается из ../src/app.html)
  test/                 тесты сервера, сети не требуют
```

## Что где живёт

| Слой | Где |
|---|---|
| Списки, пользователи, отзывы | D1 (это SQLite внутри Cloudflare) |
| Сессия | подписанная HttpOnly-кука, отдельной таблицы нет |
| Коды входа | таблица `login_codes`, хранится HMAC кода, а не сам код |
| Письма | Resend (бесплатно 3 000 писем в месяц) |
| Статика | Workers Assets, раздаётся тем же воркером |

## Развёртывание

Всё делается из папки `site/`. Нужен аккаунт Cloudflare — бесплатный.

```bash
cd site
npm install -g wrangler        # если ещё нет
wrangler login                 # откроет браузер

# 1. база
wrangler d1 create anime-tierlist
#    вывод содержит database_id — вписать его в wrangler.toml

wrangler d1 execute anime-tierlist --remote --file=schema.sql

# 2. секреты (в файлы не попадают)
wrangler secret put SESSION_SECRET      # любая длинная случайная строка
wrangler secret put RESEND_API_KEY      # ключ из resend.com

# 3. в wrangler.toml поправить OWNER_EMAIL — с этой почтой ты заходишь,
#    и твой список показывается на главной

# 4. поехали
wrangler deploy
```

Адрес получится вида `https://anime-tierlist.<твой-поддомен>.workers.dev`.
Свой домен привязывается в панели Cloudflare, раздел Workers → Custom Domains.

### Почта

`SESSION_SECRET` придумай длинным и случайным — на нём держатся подписи кук и
хеши кодов входа. Сменишь его — разлогинятся все.

Ключ Resend берётся на resend.com, регистрация бесплатная. Пока нет своего
домена, отправитель `onboarding@resend.dev` работает сразу — он уже прописан в
`wrangler.toml`. Когда домен появится, подтверди его в Resend и поменяй
`MAIL_FROM`, иначе часть писем будет уходить в спам.

Без `RESEND_API_KEY` сайт продолжает работать, но войти получится только в
режиме разработки — см. ниже.

### Фронтенд

`public/index.html` — сборка из общего исходника, руками его править не надо:

```bash
python3 ../tools/mksite.py ../src/app.html public/index.html
```

## Разработка на своей машине

```bash
cd site
wrangler d1 execute anime-tierlist --local --file=schema.sql
wrangler dev
```

Без почтового сервиса код входа некуда отправить, поэтому для локальной работы
есть `DEV_ECHO_CODE`: если задать его в `1` **и** не задавать `RESEND_API_KEY`,
код вернётся прямо в ответе API и покажется в окне входа. Как только ключ почты
появляется, код в ответах не возвращается ни при каких настройках.

## Тесты

```bash
node --test site/test/worker.test.mjs
```

Гоняют настоящий воркер: вместо D1 — встроенная в Node SQLite (`test/d1.mjs`),
вместо Resend — перехваченный `fetch`. Сети и Cloudflare не требуют.
Покрыто: вход по коду, просроченные и подобранные коды, подделка куки, права на
чужой список, каталог, смена адреса страницы, отзывы, ограничения частоты,
еженедельная сводка, размер списка.

## Устройство API

| Метод | Что делает | Кто может |
|---|---|---|
| `GET /api/config` | режим, владелец главной, кто вошёл | все |
| `POST /api/auth/request` | выслать код на почту | все, 5 в час на адрес |
| `POST /api/auth/verify` | проверить код, выдать сессию | все, 5 попыток на код |
| `POST /api/auth/logout` | выйти | вошедшие |
| `GET /api/me` · `PATCH /api/me` | профиль: адрес, подпись, уведомления | вошедшие |
| `GET /api/list/:slug` | чужой или свой список | все |
| `PUT /api/list` | записать свой список | вошедшие |
| `GET /api/lists` | каталог непустых списков | все |
| `POST /api/feedback` | написать владельцу списка | все, 5 в час с адреса |
| `GET /api/feedback` | свои входящие | вошедшие |
